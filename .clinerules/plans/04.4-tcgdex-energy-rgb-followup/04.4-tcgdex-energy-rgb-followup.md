# 04.4 — TCGdex Energy Artwork + RGB Mew (deferred, not started)

> **Status: DEFERRED — investigated 2026-09-25, no code changed.** Both asks are blocked by
> upstream TCGdex data, not by this codebase. Re-check the endpoints below; if the data has
> landed, this becomes an implementable checkpoint. Nothing here is a defect in the game:
> current behaviour is correct and shipping.

## Why this file exists

Two follow-up requests were raised against the 30c set:

1. Use the TCGdex API to supply **basic Energy card images** for 30c, and wire them into
   `pokemon-bnb` and `pokemon-pack-rip`.
2. If an **RGB Mew** now exists in the TCGdex API, add it to the 30c set — and score
   `rgb rare` as **10 points** in the pack rip.

Both were investigated directly against the live API. Neither can be implemented today.

## Finding 1 — TCGdex has the Energy card *records* but no *artwork*

The right endpoints were found:

| Thing | Value |
|---|---|
| 30c set id | **`30th`** (NOT `30th-celebration`, which 404s) |
| 30c asset path | `en/me/30th` — already used by `cardImage.ts` via `TCGDEX_SET_PATHS['30c']` |
| Energy set id | **`mee`** — "Mega Evolution Energy", 8 cards, same `me` series |
| `mee-001..008` | Grass, Fire, Water, Lightning, Psychic, Fighting, Darkness, Metal |

**`mee-001..008` map 1:1 onto `BASIC_ENERGY_TYPES` in `pack.ts`, in the same order**, so the
mapping is trivial once artwork exists.

The blocker: **there is no artwork.** Evidence captured 2026-09-25:

```
GET /v2/en/cards/mee-001    -> 200; the record has NO "image" field
GET /v2/en/cards/30th-152   -> 200; "image": "https://assets.tcgdex.net/en/me/30th/152"
```

Every candidate asset URL 404s:

| URL | Result |
|---|---|
| `https://assets.tcgdex.net/en/me/mee/001/low.png` | 404 |
| `https://assets.tcgdex.net/en/me/mee/001/high.png` | 404 |
| `https://assets.tcgdex.net/en/me/mee/001.png` | 404 |
| `https://assets.tcgdex.net/en/me/mee/001/low.webp` | 404 |
| `https://assets.tcgdex.net/en/me/mee/001` | 200 but `text/html` (CDN error page) |
| `https://assets.tcgdex.net/en/me/30th/152/low.png` | **200 image/png** (control) |

So the URL format is right and the host works — the `mee` scans simply do not exist yet.
`cardImageUrl` deliberately returns `undefined` for `supertype === 'energy'`, so the game
falls back to the tinted text face, which is the correct behaviour with no art available.

**Unblocked when:** `mee-001`'s record gains an `image` field, or
`https://assets.tcgdex.net/en/me/mee/00N/low.png` returns 200.
**Then:** drop the `supertype === 'energy'` early-return in `cardImageUrl`, add
`mee` to the set-path registry, and map type -> localId by `BASIC_ENERGY_TYPES` index.
`pokemon-bnb` and `pokemon-pack-rip` both render through the shared `PokemonCard`, so
`cardImage.ts` is the single change point for both games.

## Finding 2 — there is no RGB Mew in the API

The 30c set *does* contain Mew ex, at two numbers, and **both are already in the local data**
(`src/assets/pokemon-bnb/sets/30c/cards.json`, 158 cards):

| Number | Name | Rarity | Already present |
|---|---|---|---|
| 152 | Mew ex | Special illustration rare | yes |
| 158 | Mew ex | Futuristic Rare | yes |

Neither is RGB. Both report a single `normal` variant and nothing else:

```json
"variants": { "firstEdition": false, "holo": false, "normal": true, "reverse": false, "wPromo": false }
"variants_detailed": [ { "type": "normal", "size": "standard", "variantId": "generated" } ]
```

Corroborating checks, all negative:

- The strings `rgb` / `rainbow` appear **nowhere** in the local 30c data.
- Local `CardRarity` values are: `common | rare | double rare | pikachu rare |
  illustration rare | special illustration rare | futuristic rare`. No RGB entry.
- Sibling set `30th-c` ("30th Classic Collection") contains a Mew VMAX, but it is a
  different set with `official: 0` and no rarity data — not a 30c RGB Mew.

The highest rarity in the set is `futuristic rare` (cards 157 Mewtwo ex, 158 Mew ex).

**Unblocked when:** a 30c card (or a 30c variant) reports an RGB/rainbow rarity.
**Then:** add the card to `cards.json` and extend `CardRarity` in `cards.ts`.

## Finding 3 — the 10-point RGB tier is unreachable today

Left **deliberately unchanged**, per the decision recorded for this checkpoint.

- `pokemon-pack-battle/scoring.ts`: `BattleTier = 0 | 1 | 2 | 3 | 5 | 7`, currently topped
  by `tierForRarity('futuristic rare') === 7`. There is no tier 10 and no RGB rarity.
- Adding one now would be **dead code**: a scoring rule that no card can ever reach.

### Pre-existing fragility worth noting (not a regression, independent of this ask)

`scoring.ts` matches rarity by **exact string**, so `tierForRarity` falls through to `0` for
any rarity it does not recognise. If TCGdex introduces a new rarity string, those cards
silently score zero with no error. Consider a default-tier-with-warning (or an explicit
unknown-rarity log) before adding a new rarity to the set, so a future RGB landing cannot
land invisibly as 0 points.
