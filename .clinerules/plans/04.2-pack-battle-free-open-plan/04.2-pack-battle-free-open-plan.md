> **Status: ACTIVE — scheduled by the user 2026-09-24.** Supersedes the linear
> v2 ceremony (`pair-open {pairIndex}` / `card-reveal {pairIndex, cardIndex}`,
> one round = one pack per seat, mirrored lockstep reveal). The 04.1 plan's
> "Deferred: protocol v3" note now points here as the live plan.

> **Plan revision 2026-09-24:** the ceremony reveal/stack UX is aligned to the implemented 04.3

> immediate expanded review on Reveal All. This revision changes planned behavior only; CP1 remains completed
> and CP2 absorbs the additive v3 reveal-all/sync fields before implementing ceremony state.

## Goal

Let each player open their **own packs**, in any pack order, with every action still mirrored to the other
screen — replacing the current linear "one round = one pack per seat, revealed in lockstep" cursor. Each seat
works one focused pack at a time. Opening a pack mounts all six cards in one overlapping stack, matching the
shipped 04.3 `PokemonPackRip` CP12 presentation: normal stack mode keeps the latest revealed card visible on
top between clicks, the next click promotes and flips only the next fixed-order hidden card, and Reveal All
expands the pack for a final side-by-side review. A fully revealed pack does not auto-advance; the owner must
explicitly select/open another owned pack.

## Required inputs (user — locked, revised 2026-09-24 against implemented 04.3)

- Each player opens their **own** packs only and may choose their next owned pack in any order. Within an opened
  pack, cards reveal strictly one at a time in deterministic seeded slot order (0 through 5).
- It **still shows on both screens**: if player 1 opens their pack 1, player 1's pack 1 opens on player 2's
  screen too; if player 2 opens pack 4, that pack 4 opens on player 1's screen too.
- Both seats keep playing simultaneously — no shared round cursor, no waiting for the other seat's turn.
- One focused pack is shown at a time per seat. All six keyed cards stay mounted in one overlapping stack in
  normal mode, not a six-card grid. Offset edges are visual depth cues, never separate card-selection targets.
- One transparent button/focus target overlays the stack while hidden cards remain. Activating it reveals only
  the lowest-index unrevealed slot, using the shared `PokemonCard` flip animation. In the 04.3/CP12 pattern,
  the newly flipped card becomes the single latest face-up card visible on top; the next hidden card is then
  promoted beneath the action surface for the following click. Earlier revealed cards remain mounted but are
  not simultaneously exposed during normal step-by-step reveals.
- When all six cards are revealed one at a time, the ceremony does not auto-advance. The completed stack stays
  visible with the last revealed card on top until the owning player explicitly opens/selects another pack.
- Reveal All remains available while hidden cards remain. It marks every remaining fixed-order slot revealed
  immediately and changes the same six keyed cards from the overlapping stack to an expanded six-card row (or a
  compact two-column × three-row grid on narrow portrait layouts) for final review. It does **not** use the old
  staggered presentation queue and it does not animate cards into unrelated grid slots.

## Design constants

- Protocol **v3**: per-pack `pack-open {packIndex}` + `card-reveal {packIndex, cardIndex}` replace the
  round-based `pair-open` / `card-reveal {pairIndex, cardIndex}`. Add `pack-reveal-all {packIndex}` so the
  04.3-style expanded review is distinct from six individual reveals and mirrors on both screens. Extend the
  idempotent `ceremony-sync` snapshot to `{ opened: number[], revealed: Record<number, number[]>, expanded:
  number[] }` (union-merge) for re-dial catch-up. Bump `PACK_BATTLE_PROTOCOL_VERSION` to 3 — the version guard
  already rejects mismatched builds, so v2↔v3 cross-play fails closed with `errorVersion`.
- State: `{pairIndex, cardIndex, opened}` cursor → per-pack map keyed by pack index:
  `packs: Record<packIndex, { opened: boolean, revealed: boolean[], expanded: boolean }>` (6 reveal flags),
  plus a derived focused pack per seat (the most recently opened owned pack, including a retained completed
  pack; `null` only before that seat opens a pack). Within each pack, `revealCard` accepts only the lowest-index
  unrevealed slot, enforcing the deterministic seeded order. `pack-reveal-all` sets every remaining reveal flag
  and `expanded: true` in one authoritative action. The old `revealedAnim` cursor cascade retires. Network,
  completion, and totals use the received flags immediately; CP4 derives stacked versus expanded presentation
  from `expanded` plus the reveal flags and requires no presentation-only reveal queue.
- Ownership: `seatForPack(packIndex, totalPacks)` gates **clicks** (host = even, guest = odd,
  odd tail `both` = either seat; first click wins, union-merged). **Rendering is ungated** — every
  opened/revealed pack shows on both screens. Opening a pack selects it as that seat's focused pack; after
  card six the focus is retained as a completed pack until an explicit next-pack action sends a new `pack-open`.
- Scoring unchanged (identity scoring, Pikachu IR = 0); totals sum revealed flags per pack instead of the
  cursor prefix. Completion = every pack opened AND all 6 flags set on every pack.
- Layout: two simultaneous seat lanes (host left, guest right; one full column if an odd tail is shared), but
  **one focused pack stack per lane**, never the old pair/round view. Each lane also has a compact owned-pack
  selector/list so the player explicitly chooses the next sealed pack after the current six finish. Pack
  progress is "card N of 6" plus per-seat pack progress, not rounds. 960×540 embed, `min(100%, 960px)` caps,
  mobile-landscape `100dvh` pattern, ≤520px portrait stacking (per 01).
- Stack interaction follows the implemented 04.3 `PokemonPackRip` CP12 pattern, adapted to mirrored P2P lanes:
  all six keyed cards occupy one footprint with z/translate offsets, and the stack exposes one transparent
  button/focus target while hidden cards remain. Activating it flips only the lowest-index unrevealed slot;
  `.pkm-card-flipper` keeps the shared rotation and reduced-motion fallback. The latest revealed card gets the
  top visible slot between clicks; earlier revealed cards remain mounted beneath it, while the next hidden card
  is promoted to the actionable depth. A pack revealed fully through individual clicks stays in stack mode with
  the last card visible. Reveal All changes the same six keyed cards immediately to the expanded review grid,
  with a six-column row at normal widths and two columns × three rows on narrow portrait screens. In the
  two-lane battle layout the expanded grid may use a scaled six-card row per available lane; if a lane cannot
  fit six legible cards at 960×540, it uses the same compact two-column × three-row fallback rather than
  causing horizontal scrolling. Network/scoring state never waits for animation completion.
- Copy: `packProgress` changes from round copy to focused-pack/card progress; `packsLeft`,
  `ceremonyOpenHint`, `ceremonyRevealHint`, `actionRevealPack` (one focused pack, not “both packs”),
  `actionNextPack`, and `tutorialOpen` change meaning (no rounds, no lockstep, explicit per-seat focused pack,
  latest-visible stack behavior, Reveal All expansion, and next-pack selection). Old round keys are retired or
  reworded in the same locale pass — never leave a dead key in the dicts.
- The implemented rip page (`PokemonPackRip` + `PokemonPackRip.css`) is the UX reference. Its player-visible
  behavior must remain unchanged; 04.2 may extract a shared, co-located stack/expanded-grid presentation primitive
  from that shipped implementation to avoid duplicating keyed-card/z-index/responsive rules, but it must not
  import the solo component or couple battle ceremony state to it. Any extraction is validated in CP4.
