## Standing rules for this plan

- **Re-derive every number; copy none of it.** 04.11 produced two wrong "0 abilities"
  reports and three harness expectations that were wrong rather than the code. A number
  quoted from an earlier checkpoint is a hypothesis.
- **One checkpoint per session turn.** Validate, report, stop.
- **A blocker is printed verbatim and re-derived**, not summarised from memory.
- **A dialog that is produced is not a dialog that is seen.** CP9 exists for that reason.
- **An intermittent bug is not fixed by a green run.** CP5 has reproduced itself before any
  change is made, or it is not fixed.
- **Never start a dev server through the terminal.** 04.11's close-out session did, and it
  seized the shell; `npm run build` validates, and a browser is driven through the browser
  tools.

**Two known-broken things about the measuring instruments themselves:**
- `abilityCoverageReport` **throws** (`plainCardText` on `undefined`) unless handed
  `AbilityDef[]` — both a `string[]` and a `CardDef[]` crash it. No guard, and no type error,
  because the parameter is loosely typed.
- My first two scans reported **"0 abilities"** and were wrong: the field is `abilities`
  (a plural array), not `ability`. **A coverage number of zero is a measurement bug until
  proven otherwise** — that is why every checkpoint here re-derives rather than copies.
