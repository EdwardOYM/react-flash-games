## Required inputs

- Game: **`pokemon-bnb`** (the B&B mini battle). No registry change, no new view, no new game.
- Attacks must work end-to-end: click an attack → damage lands → Weakness/Resistance → KO → prize →
  promotion → victory. Every one of those engine steps already exists and is correct; today **none of
  them is reachable from the UI**.
- Damage counters: **1 counter = 10 damage**. The counter is a *display unit*; the engine keeps
  authoritative damage in raw points.
- The counter is shown **next to the Pokémon's health** — so health must become visible too (today no HP
  is rendered anywhere; the card face is artwork-only since CP11-E).
- A Pokémon is defeated when its damage reaches or passes its HP (rulebook: damage counters × 10 ≥ HP).
- Prizes: set face-down **from each player's own deck** at the start, **after the Mulligan phase**.
  When a player loses a Pokémon, **the opponent** draws one prize card. **A player wins when their own
  prize pile is exhausted.** All three already hold in the engine — CP5 verifies them and fixes the one
  wrong derived field.
- Persisted shape: **unchanged.** No new `AppConfig` field, no new storage key, no new highscore bucket.
  Counters, prizes and HP are session state inside `BattleState`.
- Keybinds: **none new.** `pokemon-confirm` / `pokemon-skip` keep their meaning. The Attack step is
  reached by the existing buttons; no new remappable action is introduced.
- Credits: none. This is a rules-correctness fix, not new media or a new inspiration.

## Findings that drive the plan (verified this session)

**F1 — attacks are unreachable, two routes, complementary failures.**
- `PokemonBnbGame.tsx:2029`: every per-attack button dispatches `useAttack` directly. `declareAttack`
  (`actions.ts:271-273`) calls `checkAttackPhase`, which returns `not-attack-phase` unless
  `state.phase === 'attack'`. In the Main phase **every attack click fails**.
- `CONTROLS` (`:129`) renders an "Attack" button (`beginAttack`) which *does* set `phase = 'attack'` —
  but `controls.ts:160-170` gates `beginAttack` on `isMain`, so **in the Attack step every attack button
  renders `disabled`**. Only `pass` stays enabled. The step is a dead end that burns the turn.
- `runFocusAction` (`:1305-1311`) repeats it: the comment says it "declares in the same click", the code
  dispatches only `beginAttack` and returns.
- Net effect: damage, Weakness/Resistance, KO, prize-taking and victory are all correct but unreachable.

**F2 — no health and no counter unit exist.** `PokemonCard.tsx:121` prints raw damage points in a
badge (`90`), and no HP value is rendered on the board, the bench, or the inspect panel.

**F3 — the prize rules the ask describes already hold.** `placeSetupPrizes` is called from
`chooseSetupPokemon` (`setup.ts:202`) — i.e. after the Mulligan phase — and takes from **that side's own
40-card deck**; `performKo` (`turns.ts:134-135`) gives one prize to `foeOf(koSlot)`, the KO'd side's
board; `checkVictory` (`turns.ts:95-101`) declares the win when `prizeCount === 0`. CP5 asserts all of it.

**F4 — a wrong derived field.** `snapshots.ts:50` computes `prizesTaken: side.prizeCount - side.prizes.length`,
but `takePrizeCard` (`turns.ts:120`) keeps those two in sync, so the field is **always 0**. Harmless
today (the board reads `side.prizeCount`) but it is a false public field on the guest snapshot.

**F5 — the data is counter-clean.** All 155 Pokémon in `src/assets/pokemon-bnb/sets/30c/cards.json` have
HP that is a multiple of 10 (range 30–330), so 1 counter = 10 damage converts with no rounding
ambiguity. HP counter counts stay in 3–33.

## Damage-counter rule (CP1, locked)

- Engine authority stays **raw damage points**; `isKnockedOut` is untouched (`damage >= card.hp`). The
  counter is derived for display only, so a UI change can never alter a match result.
- `hpCounters(hp) = Math.ceil(hp / 10)` — `ceil`, not `round`, so a hypothetical non-multiple-of-10 HP
  can never show a Pokémon with damage as still having positive remaining health.
- `damageCounters(damage) = Math.floor(damage / 10)` — `floor`, because a KO at raw `damage >= hp`
  implies `floor(damage/10) >= ceil(hp/10)` for every value in the set.
- `remainingCounters(pokemon) = max(0, hpCounters(card.hp) - damageCounters(pokemon.damage))`.
- The board log line keeps **raw damage** (`pokemonBnb.log.damageDealt` `amount`) because that is the
  damage value itself; the counter is the visual unit. The two are derived from one field, so they
  cannot disagree.
- Readout shape per in-play Pokémon: `HP {hp}` then `{n} counters` (or a "no damage" state at 0),
  placed beside the card. Bench and the inspect panel get the same treatment as the Active.

## Attack flow after CP2 (locked)

- `useAttack` is legal in **Main** *or* **Attack** phase. On success from Main the engine sets
  `phase = 'attack'` before resolving, so the log/phase header still shows the step the attack came from.
- `beginAttack` keeps its current meaning (open the step) and stays on the bar.
- New `ControlId 'useAttack'` in `controls.ts`: enabled when `isMain || isAttack`, the Active exists, it
  is not Asleep/Paralyzed, it is not the first player's Turn 1, and the card has ≥1 attack. Each attack
  button additionally checks `canPayCost(active.attachedEnergy, attack.cost)` and reports the existing
  `insufficientEnergy` reason. `beginAttack` keeps its own rule unchanged.
- The action bar's attack buttons use `controls.useAttack` (never `controls.beginAttack`), so they stay
  live in the Attack step and the step is no longer a dead end. **Pass remains legal in both phases.**
- `focus.ts` gates its attack entries on the same `useAttack` rule (its existing comment already claims
  one-click declare), and `runFocusAction` dispatches `{ type: 'useAttack', attackIndex }` in a single
  call — the comment becomes true.
- No new error codes are needed: `pokemonBnb.error.notAttackPhase` and
  `pokemonBnb.error.insufficientEnergy` already exist in all three dictionaries.

## Prize flow verification (CP5, locked)

- Assert with a harness, changing nothing unless an assertion fails: prizes come from each side's own
  deck (`len(prizes) + len(deck) + len(hand) + len(discard) + len(active/bench)` stays consistent);
  prizes are set only after `setup.phase` has passed Mulligan; every KO gives exactly one prize to the
  **opponent**; `winReason === 'prizes'` fires only when the winner's own pile hits 0; taking the last
  prize ends the match immediately.
- CP5's code change is limited to `snapshots.ts:50`: derive the real taken count
  (`state.prizeCards - side.prizeCount`, matching `turns.prizesTaken`) so the guest snapshot stops
  reporting a constant 0, and assert `toSnapshot → applySnapshot → toSnapshot` stays idempotent.
