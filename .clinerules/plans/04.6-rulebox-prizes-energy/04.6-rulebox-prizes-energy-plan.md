## A — rule-box prize rule (locked)

```
prizesForKnockOut(card) = card.suffix?.toUpperCase() === 'EX' ? 2 : 1
```

- Lives in `cards.ts` next to the card type it reads, pure, no React and no engine import.
- `performKo` takes that many, **bounded by what is actually in the pile**: it loops at most
  `prizesForKnockOut(knockedOut)` times and stops early when the pile empties. `takePrizeCard` already
  calls `checkVictory`, so a pile emptied mid-loop ends the match, and the existing `if (state.over) return`
  keeps the promotion gate from firing after a win.
- Rulebook edge case to assert: **1 prize left + an ex knocked out → the taker takes the 1 remaining card
  and wins.** Taking a second from an empty pile must be impossible, not silently skipped.
- `prizesTaken()` (which feeds the "for each Prize card you have taken" bonus) is unchanged and stays
  correct, because it derives from the configured total minus what remains.
- A **new translated log line** names the rule box and the count, so a 2-prize take is never a mystery.

## B — Energy readout (locked)

- One chip per **distinct** `provides` type, carrying the count of that type, in `BASIC_ENERGY_TYPES`
  order (`pack.ts`) with anything unrecognised last, so a row is stable rather than hand-ordered.
- Each chip is a **colour swatch + number**. The swatch is `aria-hidden` decoration, so the only
  player-facing string is the accessible name — built from a **new translated** `energyType<Key>` map
  (mirroring the existing `CONDITION_KEYS` / `SET_LABEL_KEYS` id→key maps), never a hardcoded English
  type name. Card names are data, but the synthetic `Fire Energy` name is English-only, so it is used
  for nothing player-facing here.
- The total stays visible as well (it is what the old `⚡n` showed), so nothing currently readable is lost.
- CSS is added to `BattleBoard.css` only. The per-type gradient tints belong to `PokemonCard.css`
  internals and are **not** re-declared or imported for this.
