# 04.8 — The remaining 30c attack effects: spread, then a choice seam (pokemon-bnb)

> **Checkpoint protocol**: ONE checkpoint per session turn; after each, the narrowest relevant
> validation (`npm run build`, plus `npm run lint` for code), report files + behaviour + result, then
> STOP. Sub-steps where a checkpoint has more than one surface.
>
> **Scope.** 04.7 left 69 of 99 distinct attack texts reporting `unsupported` (101 of 154 instances).
> This plan works that backlog down in **risk order**, not volume order, and the order comes from a
> measurement of the real set rather than a guess.

## Correction to an earlier claim (measured 2026-09-26)

I previously told the user the engine was "a pure synchronous function with no seam to host a picker".
**That was overstated, and the correction matters.** There *is* a working interaction seam already:
the **Knock-Out promotion gate** is exactly the pattern a choice needs —

1. the engine sets a state flag (`BattleState.pendingPromotion`, plus an ordered `promotionQueue`);
2. `processAction` **refuses every other action** with the `'must-promote'` code while it is set (the
   `pendingPromotion` branch sits ahead of the main switch in `actions.ts`);
3. the UI renders a `role="dialog"` gate (`bnb-promote-gate`) where the player picks a Bench index and
   dispatches `promoteActive`, which resumes play.

So "add a picker" is a **generalisation of an existing pattern**, not new architecture. What genuinely
*is* new is in CP3 below — and it is a privacy question, not a mechanism question.

## Progress

- [x] CP0 — Plan written, after measuring the backlog and **correcting the "no seam" claim**. **Gate:
      `npm run lint`.**
- [x] CP1 — **Interaction-free, lowest risk:** spread to every opponent Pokémon (honouring the printed
      "Don't apply Weakness and Resistance" rider), the same filtered to Pokémon **ex** (reusing 04.6's
      `suffix`), and "Flip N coins, N' damage for each heads". **Measured: 3 texts / 7 instances** (the
      plan's "5 texts / 9 instances" was a pre-measurement estimate; 104 Ferrothorn and 099 Hydreigon are
      *compound* and deliberately stay unsupported). **No interaction at all.**
      **Done:** two new clause kinds — `spreadDamage { amount, exOnly }` and `coinFlipDamage { amount,
      flips }` — plus `resolveSpreadAttack`, a dedicated resolver, because a spread cannot be folded into
      `base` (that is applied to the Active alone, with Weakness/Resistance). The Active is resolved
      through the ordinary Weakness/Resistance path and every Benched target takes the flat printed amount.
      **`performBenchKo` is new in `turns.ts`:** a Benched knockout opens NO promotion gate, yet still pays
      the rule-box Prize cards (benching an ex is exactly how a player risks two prizes). 04.6's prize
      loop was extracted to `settleKnockOutPrizes` so the Active and Bench paths share one implementation
      rather than duplicating it. Benched knockouts settle **before** the Active, because `performKo`
      opens its promotion gate onto whatever Bench is left.
      **Three data traps found and handled:** (1) the set prints `"Pokemon ex ."` with a space before the
      period, so an `$`-anchored pattern silently misses all three Mewtwo ex attacks; (2) the printed
      "(Don't apply Weakness and Resistance for Benched Pokémon.)" reminder is stripped *before*
      sentence-splitting, and the empty sentence that leaves behind is filtered — otherwise it became an
      empty `unsupported` clause and the all-or-nothing guard read the whole attack as unparseable;
      (3) Gholdengo's coin attack is **not** `attacks[0]`, and Gholdengo is a **Stage 1**, so no setup
      handshake can ever produce it — the coin clause is card-agnostic, so it is driven from a Basic
      attacker using Gholdengo's own printed attack definition.
      **All-or-nothing:** Ferrothorn reads "50 damage to each of your opponent's Pokémon … This Pokémon
      also does 130 damage to itself." Applying the spread while dropping the self-Knock-Out would be a
      materially wrong game state, so a spread sharing a sentence with anything unparseable is dropped
      wholesale.
      **Gate: build + lint + 207-assertion harness (deleted after use) — build clean, lint 0/0, 207/207.**
      The harness proves, on the real 30c data and a real setup handshake: 30/50 to the Active and every
      Bench; Weakness ×2 on the Active and **no** multiplier on the Bench; the ex filter skipping a
      non-ex Bench; a Bench knockout taking 1 prize (2 for a benched ex, with the 04.6 rule-box log) and
      opening **no** promotion gate; emptying the pile from a Bench knockout winning; the Active settling
      after the Bench so no gate survives an emptied Bench; a seeded, deterministic multiple-of-50 coin
      result; near-miss texts that must stay `unsupported`; and 04.5/04.6/04.7 regressions (counter/KO
      agreement across the set, a single-target ex KO still paying 2 and still gating, the 04.7 per-prize
      clause, and a byte-identical snapshot round trip). Registry coverage moved **30 → 33** fully-parsing
      texts and **69 → 66** unsupported — measured, not assumed.
      **Harness-only lessons (no product code changed for a test):** 30c ships **no Energy cards**
      (cards.json is 155 Pokémon + 3 Trainer; Energy is generated separately), so a per-energy fixture
      would need a synthetic card; and "any card with a printed damage" can select a 04.7 `extraPrizeOnKo`
      attack, which pays a third prize and is not what a 2-prize regression is about.
- [ ] CP2 — **The choice seam, visible zones only:** generalise the promotion gate into a reusable
      pending-choice so a player can choose a *target Pokémon* (damage a chosen opponent Pokémon, place
      counters, heal a chosen Pokémon). Those zones are **already public** in the snapshot, so **no
      privacy change and no new wire kind.** **Gate: build + lint + a harness proving the engine refuses
      every other action while a choice is pending (the `must-promote` discipline), the target list is
      correct, an illegal target is rejected, and an out-of-band action cannot skip the choice.**
- [ ] CP3 — **Deck search — BLOCKED on a decision, not on engineering.** A picker over the deck is
      mechanical, but the deck is currently hidden from **both** seats (`SnapshotSide` carries only
      `deckCount`; the contents never leave the authoritative state). Letting the acting seat see and
      choose from their own deck means their snapshot must start carrying their own deck contents — a
      **privacy-sensitive change to the snapshot contract in a host-authoritative P2P game**, where the
      host builds both seats' views. That is a product decision (leak risk, snapshot size, behaviour on
      disconnect) and is **not** answered here.

## Locked rules for CP1

- **Spread never applies Weakness or Resistance to Benched Pokémon.** That rider is printed on the card,
  so the harness must assert the Bench takes flat damage while the Active still goes through the normal
  `computeAttackDamage` path. Getting this wrong is exactly the "wrong effect" failure the engine
  forbids.
- **A spread that KOs several Pokémon must settle every knockout**, including each Prize take and the
  ordered promotion queue, rather than stopping at the first.
- **The ex filter reads 04.6's `suffix`** — one identifier, two rules.
- **The coin variant reuses 04.7's bounded approach**, and N is printed on the card, so there is no
  unbounded loop to cap.
- Near-miss text still reports `unsupported`, as in every 04.7 family.

## Hard rules

- 01-flash-game-builder: CP1 adds no player-facing copy beyond the existing `pokemonBnb.log.*` lines;
  CP2 adds a dialog, which is real UI work needing the 960×540 cap and the landscape/portrait
  breakpoints.
- 02-diagram-flow-checks: no new `AppConfig` field, no new storage key. **CP2 must not change the
  snapshot contract** — that is CP3's decision, and keeping it out is deliberate.
- 03-skills: not a new game. 04-terminal-commands: `git --no-pager`, non-interactive, `---done---`.
- 05-agent-discipline: one checkpoint per turn; throwaway harnesses, deleted after each run; never
  rewrite a harness through PowerShell (it corrupts UTF-8 — see 04.7 CP1).
- The engine's standard stands: **a wrong effect is worse than a missing one.**
