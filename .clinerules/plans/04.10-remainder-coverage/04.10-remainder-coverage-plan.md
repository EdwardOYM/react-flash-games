# Implementation Plan — 04.10: the remaining card text (04.10)

> **Checkpoint protocol** (from `05-agent-discipline.md`): run ONE checkpoint per session turn. After each
> checkpoint run the narrowest relevant validation, report *files + behaviour + result*, then STOP and wait
> for "next".
>
> **Scope:** `pokemon-bnb`'s engine only, continuing 04.9. Not a new game, no persistence, no protocol
> change unless a checkpoint below says so explicitly.

## The measurement this plan is built on (CP0, not an estimate)

passive Ability texts. This plan re-measured both by running the real parser over every card in
`src/assets/pokemon-bnb/sets/30c/cards.json`, so every row below is an observation, not a guess.

## Progress

- [x] **CP0 — this plan, written from a measurement.** A throwaway probe ran the real parser over every

- [x] **CP1 — Groups A, B, J: the discard/deck picks. 4 texts / 5 instances** (081 Gimmighoul,
      048 Pikachu, 103 Dialga, 109/156 Salamence ex). **The plan's prediction held: these are
      target rules, not new machinery.** 04.9 CP4 had already made a choice resolve N times
      from a live zone, and CP3 had left `pickFromDiscard`'s `to` open for exactly this, so
      the whole checkpoint is one clause widened and one filter table extended.
      **`searchDeckUpTo` was WIDENED, not duplicated — and both unions had to move together.**
      It gained `from: 'deck' | 'discard'`, `to: + 'deck'`, `requireType?`, and three filters
      (`basicEnergy`, `pokemon`, `pokemonOrEnergy`). `ParsedEffect` and
      `PendingChoice.effect` each declare this kind **separately**, so widening only one
      would not compile — and a drift between them would be a silently unreachable card
      rather than an error. A separate `searchDiscardUpTo` would have been a *fourth*
      near-identical kind, which is exactly the kind that drifts.
      **The cap is bounded by ELIGIBLE cards, not by the zone's size.** Park time counts
      what actually qualifies, so "up to 3 Dragon" over a discard holding one Dragon and
      two non-Dragon is a cap of **1** — rather than a picker that silently offers nothing
      on the second pick. Asserted for 109/156 and for 103 (a Stadium is neither a
      Pokémon nor Basic Energy, so a discard of one Stadium + one Pokémon caps at 1).
      **"Basic Energy" excludes SPECIAL Energy**, which is the card-data rule
      (`provides === undefined`), not a name check. Asserted: a discard of only special
      Energy and a Pokémon parks **nothing** and still closes the turn.
      **The resolver picks the pile from the CLAUSE, and refuses a cross-zone forgery.**
      The target's `zone` is checked against the clause's `from`, so a deck entry cannot be
      smuggled into a discard clause even when its `cardId` happens to match. That is a new
      assertion 04.9 did not have, because 04.9 only ever read one zone.
      **081 is coin-gated, so it is a separate kind rather than a `searchDeck` filter** — a
      filter cannot express "only on heads" without adding a flag to every caller. The flip
      is resolved at resolution, so tails simply does not park; the harness sweeps **24
      seeds and asserts BOTH outcomes occur**, because a coin gate that never fires would
      still pass a single-seed test.
      **Gate: build + lint + 139-assertion harness (deleted after use) — build clean,
      lint 0/0, 139/139.** Also asserted: a discard pick takes 0, 1 or 2 with the deck
      shrinking by exactly the number taken; taking one then finishing **keeps** it; two
      **identical** cards are both pickable (a bare-id filter would collapse them); a
      Stadium in a discard is not offered by 103; a non-Dragon is not offered by 109; the
      Bench cap ends a "up to 3" bench-search early at exactly 5; out-of-range indices, a
      forged `cardId`, a cross-zone target and the wrong seat are each refused with the
      choice intact; and 04.8 CP6's privacy invariant is re-asserted — the discard is
      public so the actor sees it, while the opponent's hand and deck stay withheld.
      Regressions: 013 and 076 still read the **deck** and behave exactly as in 04.9.
      **Coverage, measured: 129/154 attack texts parse fully, 25 unsupported (21 unique)** —
      up from 124/35.
      **04.9's near-miss lesson fired a FOURTH time, and the harness caught it.** I filed
      "up to 5" and "up to 3 **Water**" as near-misses; they are the same shape with
      different numbers — legitimate sibling cards that must parse. They are now asserted to
      parse to **their own** cap and **their own** type filter, which is a stronger

      **Honest limits:** nothing has been seen in a browser; 103's printed "shuffle … into

- [x] **CP2 — 087's mirrored damage reduction, and the per-head coin families. 3 texts /
      4 instances** (087 Nidoran, 099 Hydreigon, 125/146 Maushold). A `lessDamageDealt`
      duration (the mirror of 04.9 CP5's `lessDamageTaken`), a
      `lessDamageDealtWhileActive` passive id, `activeDealtReduction`, and two per-head
      clause kinds.
      **THE HARNESS CAUGHT ME MISREADING THE CARD, and the fix is the most important
      thing in this checkpoint.** I first wrote `subject: 'attacker'`, reasoning that
      087 "reduces what the holder DEALS". That is wrong. Growl is **0 damage**, so the
      "Defending Pokemon" it refers to is simply the **opponent's Active at the moment
      it resolves** — the effect SLOWS THE OPPONENT, and its `+1` window exists precisely
      because that is when the opponent's Active gets to attack. With `subject: 'attacker'`
      the duration would have ridden the Nidoran and reduced its output **while it is
      benched and unable to attack at all** — a rule that can never fire, which is the
      quietest possible wrong effect and one no parser test would ever catch. It was the
      *behavioural* test that exposed it: a live exchange read 60 instead of 30.
      The direction is now pinned by an explicit control — `activeDealtReduction` returns
      **0 for the user of the attack and 30 for the opponent's Active** — so the two
      directions can never be conflated again.
      **125/146's flip count is stored as a card NAME, not a number.** "Flip a coin for
      each Maushold you have in play" depends on the board, so freezing a count at parse
      time would be wrong the moment the board changes. The clause carries `perOwnName`
      and resolution counts via the existing `nameMatches` (which already tolerates the
      "ex" suffix). Asserted by running the **same seed** against a one-Maushold and a
      two-Maushold board: two Maushold flips twice as often and can never discard fewer.
      099's count IS printed ("Flip 3 coins"), so `flips` is a literal number — the two
      are different shapes and get different fields.
      **Per-head effects are bounded by the WORLD, not just the coin.** 099 discards at

      Energy discards one rather than reporting two misses. 125/146 stop when the
      opponent's deck runs dry and a short batch is **not padded** — discarding cards
      that do not exist would be a wrong effect. Both asserted across a 30-seed sweep,
      with `discarded + remaining` invariant to prove no card is created or lost.
      **The reduction is read BEFORE the Weakness multiplier**, per the printed
      "(before applying Weakness and Resistance)": `(60 − 30) × weak`, **not**
      `60 × weak − 30`. Asserted against the pure `computeAttackDamage` — deliberately
      NOT a live attack, because 60 damage against a 60-HP Nidoran Knocks It Out
      whenever a Weakness applies and leaves `active` null, which is 04.9's
      fragile-defender trap biting for the fifth time. The pure function has no KO path.
      **Gate: build + lint + 155-assertion harness (deleted after use) — build clean,
      lint 0/0, 155/155.** Also asserted: 028's text is **not** mistaken for 087's (they
      are opposite directions, and both exist); 04.8 CP1's per-head **damage** clause is

      **Coverage, measured: 133/154 attack texts parse fully, 21 unsupported (18

      **Harness lessons (two, and the first is a real product bug I shipped for one

- [x] **CP3 — Group E: "during your opponent's LAST turn" memory. 3 texts / 4 instances** (005
      Tropius, 091 Umbreon, 085/138 Lycanroc). **The first new engine state in two plans**,
      and the design decision is the checkpoint: both memories are stamped with a **TURN
      NUMBER** and read with `=== state.turn - 1`, rather than being a counter that some
      reset step must clear. That makes compounding *structurally impossible* — a hit from
      two turns ago is simply not "last turn" — and it means `applyEndTurn` needs **no
      reset code at all**, which matters because 04.9 already proved `applyEndTurn` has
      more than one exit and a flag cleared on each would eventually be missed.
      **THE FLAG IS ON THE SIDE, NOT THE POKEMON, and the reason is mechanical rather than
      stylistic.** I first wrote a per-Pokémon `koByAttackTurn` for 005/091 and then
      deleted it: `discardKnockedOut` destroys a KO'd Pokémon's `InPlayPokemon` and keeps
      only the `CardDef`, so a per-Pokémon flag is **gone exactly when the clause needs
      it** — and the clause is side-wide ("ANY of your Pokemon") besides. The side field
      is the only place it can live. The per-Pokémon half (085/138's damage taken) is
      unaffected, because that Pokémon is still in play.
      **The KO is recorded ONLY at attack sites, never inside `performKo`.** Poison and
      Burn KOs run through the same `performKo`, and 04.10's text is specific about "by
      damage from an attack" — a Between-Turns poison KO satisfying it would be a wrong
      effect. Asserted directly: a Poison KO really happens (`active` becomes null) and
      `koByAttackTurn` is still -1. Both the Active KO and the **bench** KO from a spread
      are covered, because 005 says "any of your Pokemon" and an Active-only
      implementation would pass a lazier test while being wrong.
      **Recording is placed so a prevented hit leaves no memory.** `recordAttackDamageOn`
      runs *after* the `preventAllDamage` test has already forced the amount to 0, so a
      shielded Pokémon cannot "remember" a hit it never took. Spread damage records too —
      otherwise a benched-then-promoted Lycanrock would answer 0 after a spread.
      085/138's clause carries **no `amount` at all**: the printed text says "that much",
      so the number is only knowable at resolution, and an `amount` field would be invented.
      **The wire:** the side flag is carried verbatim on `SnapshotSide` (public — both
      players watched the KO — and it names no hidden zone, so the privacy boundary is
      unchanged); the per-Pokémon memory rides inside `cloneInPlay`'s JSON copy, which is
      why it needs no explicit produce or restore line. `?? -1` on restore so a snapshot
      from an older host cannot rebuild to `undefined` and silently disable both cards.
      **Gate: build + lint + 61-assertion harness (deleted after use) — build clean,
      lint 0/0, tsc clean, 61/61.** Includes the **anti-compounding gate** proper (a
      Pokémon hit for 60 on turn 6 and 60 on turn 8 reads **60**, not 120), same-turn
      accumulation, a **5-case near-miss suite** (a KO with no "by damage from an attack"
      rider, "your last turn" not the opponent's, a printed number on 085's shape, damage
      not from an attack, and "this Pokémon" vs "any of your Pokémon" — opposite scopes),
      plus a regression that 04.9's `bonusDamageIfDefenderDamaged` and 085/138 are not
      confused with each other.
      **Coverage, measured: 137/154 attack texts parse fully, 17 unsupported (15 unique)**
      — up from 133/21 after CP2.
      **Harness lessons — FIVE vacuous fixtures, the most in any checkpoint so far, and
      three were the same root cause.** (1) `battle()` starts on turn 5 with the HOST
      active, and my first pass helpers each ran the *host's* `pass`, so the guest never
      got a turn and every attack silently no-opped. (2) `declare` advances a turn, which
      is easy to forget when computing which turn a hit is stamped on. (3) **Tropius at
      55 damage plus a 60-damage gym is 115 against 120 HP — no KO at all**, and the block
      reported the resulting "flag not set" as an engine failure when the assertion was
      simply vacuous. (4) **An empty Bench ends the match as `no-pokemon`, so
      `applyEndTurn` never runs** and the turn never advances — twice (the host's KO, then

      memory does not survive a turn boundary" and were pure fixture faults. The recurring
      lesson holds: **a passing suite is not evidence, and neither is a failing one, until
      the fixture is proven to have exercised the path.** The engine was correct in all five
      cases; every one of them was my harness lying to me.
      **Honest limits:** nothing has been seen in a browser, and the two halves of the

- [x] **CP4 — Group C + 063: attach Energy FROM a zone. 3 texts / 3 instances** (007 Cherrim,
      042 Pikachu, 063 Mewtwo). The plan predicted this was "a search composed with a
      target pick"; it is right that a second pick is needed and **wrong that the three
      cards share one rule** — they are three different destination modes, and that
      difference is the whole checkpoint.
      **NOT a fourth `to` on `searchDeckUpTo`.** `searchDeckUpTo` always moves a card
      INTO a pile; these move a card ONTO a Pokémon, which carries the once-per-turn
      Energy interaction and three destination rules no `to` can express. A new
      `searchAttachEnergy` clause plus an `attachStaged` second stage.
      **`target` is the entire difference and all three values are needed:** `'attacker'`
      (042, "to THIS Pokémon" — no second pick at all), `'oneForAll'` (063, "to 1 of your
      Pokémon" — one destination for the whole set) and `'perCard'` (007, "in any way you
      like" — a destination per card). Asserted in BOTH directions: 063's two cards are
      **forced onto the same Pokémon**, and 007's two are shown **splitting across the
      board**. Either card alone would have passed a lazier test while being wrong.
      **A pick cannot choose a card AND a destination, so it is split across two parked
      choices, with the cards held in a new `staged` buffer on the choice.** The buffer
      holds the CardDef rather than re-finding it by id, because a Deck holds DUPLICATES
      and "the Energy I picked" is therefore not an identity. It is copied out of the
      pile, not referenced, since the pick splices the card out.
      **`attachStaged` CARRIES ITS PARENT CLAUSE, and that is not decoration.** The first
      implementation dropped it, and 007 broke in a way no parser test could see: stage
      two had no idea the remaining `remaining` belonged to a per-card sequence, so it
      closed the turn after the FIRST card and 007 could only ever attach one Energy. The
      parent is what lets `perCard` re-park the pile and `oneForAll` close. The clause
      shape is declared ONCE (`SearchAttachEnergyClause`) and referenced from both
      `ParsedEffect` and `PendingChoice`, precisely because the two must not drift.
      **`finishChoice` had to learn the staged case.** Declining the rest of 063's "up to
      2" with one card already lifted would have closed the turn and **destroyed it** —
      it is spliced out of the pile and lives only in `staged`, so it would be in no zone
      at all. Declining now parks the destination pick instead.
      **The filter is re-validated at RESOLVE time, not only at park time.** A forged
      index naming a non-Energy card is refused, and 042's `energyType` is re-checked —
      so "Basic Lightning Energy" cannot be satisfied with a Fire Energy. A SPECIAL Energy
      is never offered (`provides === undefined`), asserted directly.
      **042's cap is the HEADS, resolved at park time** and bounded by `MAX_COIN_FLIPS`
      like every other until-tails loop, then intersected with the ELIGIBLE card count.
      Swept across 60 seeds asserting **both** a 0-heads result (parks nothing — a picker
      with a legal target the card never authorised is the soft-lock every other arm here
      refuses) and a heads result, so the 0-case is not vacuous.
      **THE ONCE-PER-TURN ENERGY LIMIT, and the reading this engine takes.** The printed
      cards settle it, not my judgement: 007 says "up to 2", 063 "up to 2", 042 "up to the
      number of heads" — **none is reachable under a one-per-turn cap**, so treating that
      limit as gating these effects would silently disable all three. The card effect
      therefore does not consume `energyAttachedThisTurn` and does not set
      `energyAttachedTurn`, leaving the hand limit intact and independent: asserted in both
      directions (a hand attach is still refused when the limit is spent; and still
      available on the host's next turn after the card effect, counting against that
      turn's own limit). **This is a rules reading, flagged for review.**
      **`shuffleDeck` needed no new field** — 04.8 CP3-B already treats the trailing
      "Then, shuffle your deck." as a no-op, so a `shuffleAfter` flag would be dead code.
      **Gate: build + lint + 165-assertion harness (deleted after use) — build clean,
      lint 0/0, tsc clean, 165/165**, plus a **5-case near-miss suite** and a regression
      that 048 (discard Energy to HAND) and 063 (discard Energy to a Pokémon) are not
      cross-wired — same pile, opposite destination, the pair most likely to be confused.
      **Coverage, measured: 140/154 attack texts parse fully, 14 unsupported (12
      unique)** — up from 137/17 after CP3.
      **TWO REAL ENGINE BUGS the harness caught, both invisible to a parser test.**
      (1) `attachStaged` never nulled `pendingChoice` before `applyEndTurn`, so every
      007/063 attach ended the turn with a finished choice still parked and

      **Harness lessons (four, all fixture faults, the usual pattern).** (1) I seeded the

- [x] **CP5 — Group H + I: "attach ANY number" (054/150) and shuffle-self-into-deck
      (073/136). 2 texts / 4 instances.** `SearchAttachEnergyClause` gains `from: 'hand'`
      and an `optional` flag; a new `shuffleSelfIntoDeck` choice kind; a `hand` zone on
      both `ChoiceTarget` and `PendingChoice.source`.
      **THE PLAN WAS WRONG ABOUT GROUP I, and the text settles it.** The plan said both
      groups "need a choice kind with a per-card target pick". 073/136 print "You may
      shuffle **this** Pokemon and all attached cards into your deck" — there is no target
      to pick and nothing to choose between. It is a **single-entry optional choice**,
      the same shape 04.9 CP7 gave 066/152/158's optional switch. It is still a choice
      rather than an automatic effect because the printed **"You may" is a permission**:
      applying it unconditionally would be a *stronger* effect than the card prints, which
      this engine ranks worse than a missing one. Both directions are asserted — accepting
      moves the card, declining leaves it in play.
      **"ANY number" NEVER REACHES `remaining` AS `Infinity`.** 054/150's printed cap is
      unbounded, and `JSON.stringify(Infinity)` is `null`, which would silently break the
      snapshot round trip 04.8 CP6 established. The cap is resolved at park time to the
      **eligible** count — which is also the honest answer, since you cannot attach more
      Energy than you hold. Asserted three ways: the cap equals the hand count, it is
      finite, and **it survives a snapshot round trip** (an `Infinity` would not).
      **"All attached cards" includes a Tool, not just Energy** — asserted with 2 Energy
      and 1 Tool riding back to the deck together with the Pokémon. Leaving the Tool
      behind would orphan a card that is in no zone at all.
      **THE EMPTY ACTIVE SPOT IS THE NON-OBVIOUS PART.** Shuffling the attacker away
      leaves the Active vacant, so the same `promotionQueue`/`pendingPromotion` gate
      `performKo` sets is raised here, letting one `promoteActive` action serve both. The
      alternative — silently leaving a null Active — is a soft-lock, and 04.10 has now seen
      that failure mode twice. With an empty Bench it is the engine's existing
      `no-pokemon` loss; inventing a new outcome would be a rules change, so none was.
      **`optional` is a permission that rides the EFFECT, never the attack name**, and its
      ABSENCE is load-bearing: 007/042/063 print no "may", so their picks must not be
      declinable or the player could skip a printed effect. Asserted directly on the

## Why the ordering is what it is

Ordered by **mechanism needed, ascending**, deliberately NOT by instances covered:

1. **CP1** reuses two seams 04.9 already built and proven (live-zone picks, N-pick resolution). It should
   be the cheapest real coverage in the plan.
2. **CP2** adds one effect kind and reads an existing coin count.
3. **CP3** is the first checkpoint in a long time that adds *per-turn memory*. It is placed **after** the
   cheap work precisely because it is the first thing that can go subtly wrong, and it is also the one
   that most needs a browser to trust.
4. **CP4–CP5** compose existing mechanics but in new orders (search→attach, player-directed multi-attach).
5. **CP6** replaces the parser's splitter — the single highest-risk change in the plan, because it can
   regress *already-working* clauses. It is late on purpose; if it lands, the whole 124-text baseline
   must be re-measured, not just the two new ones.
6. **CP7–CP8** are the rules questions.

## The engine's standard, restated for this plan

**A wrong effect is worse than a missing one.** Concretely, for every clause added here:

- the pattern is **anchored end-to-end**, and a near-miss assertion proves it does not fire on the
  neighbouring shape. Note 04.9 caught itself filing a real card as a near-miss **three times** — a
  "different energy type" text and a "different number" text are legitimate sibling cards, not
  near-misses, so each candidate is questioned before it is asserted;
- a clause that cannot be honoured **falls through to `unsupported`**, never applies partially;
- anything that reads board state is asserted **with a control case that has the state absent**.
  04.9 found a green test suite **four separate times** that was really measuring a refused action
  (missing Energy, a deck-out, an Asleep attacker, Checkup poison) rather than the rule under test. That
  is the dominant failure mode of this engine and the thing to watch for in every checkpoint here.
