# 03.2.CP6 — B&B Symmetrical Board and Attachments

> Parent: `03.2-Pokemon-B&B-revamp-plan.md`. Depends on CP5.

## Scope

Create co-located `BattleBoard.tsx` and `BattleBoard.css`. Use one side component for both seats, with
the opponent side flipped. Render the shared Stadium, Active, Bench up to five, Prize, Deck, Discard, and
private-own/public-opponent hand treatment. Represent attached Energy and Tools, and add shared Stadium
state. Keep hidden zones hidden in snapshots and preserve uniform card sizing.

Responsive requirements: 960×540 16:9, `min(100%, 960px)`, `minmax(0, 1fr)`, mobile-landscape
`100dvh`/safe-area layout, and narrow portrait stacking without horizontal scrolling.

## Files

New `BattleBoard.tsx`/`.css`, `PokemonBnbGame.tsx/css`, engine types/snapshots/helpers, locales.

## Validation

Board DOM/zone audit, snapshot privacy, same-side reuse, opponent flip at 960×540/520px/landscape,
no overflow, keyboard/screen-reader labels, build + lint.

## Progress

- [x] CP6 completed 2026-09-25.

## What shipped

- **New `BattleBoard.tsx`** — `BattleBoard` (Stadium lane + both lanes) and `BattleSide`, which renders
  **both** seats. There is no self-only or foe-only panel, so the two sides cannot drift.
  - Opponent mirrored with `column-reverse` (CSS flex order), **not** a transform: a transform would
    flip every translated label and card name upside down and reverse screen-reader reading order.
  - Zones: shared Stadium, Active, Bench (up to five), Prize, Deck, Discard, Hand.
  - Attachments render as chips — an Energy count plus the Tool's name — rather than full faces, so a
    heavily charged Pokemon cannot overflow the 16:9 stage.
  - Own hand is named and selectable; the opponent's is a count only. The gate is the absent
    `onSelectHand`, so the opponent lane is read-only by construction.
- **New `BattleBoard.css`** — co-located, `min(100%, 960px)`, `minmax(0, 1fr)` tracks, reuses the shared
  `--pkm-card-w` token, and carries its own mobile-landscape and narrow-portrait overrides.
  No `overflow-x` anywhere.
- **`PokemonBnbGame.tsx/.css`** — the inline `BattlePanel` component and its duplicated rules are
  deleted; the game now renders `<BattleBoard>`. Only the shared `.bnb-side-name` primitive stayed.
- `BattleState.stadium` (added in CP4) is now surfaced on the board.

## Bug found and fixed during validation

The opponent's hand initially rendered **interactive pick buttons**, because hand picks were gated on
card visibility rather than on ownership. Fixed by gating on `onSelectHand`, which is only supplied to
the viewer's lane.
