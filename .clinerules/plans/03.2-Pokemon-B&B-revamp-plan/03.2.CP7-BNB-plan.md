# 03.2.CP7 — B&B Action Controls and Promotions

> Parent: `03.2-Pokemon-B&B-revamp-plan.md`. Depends on CP6.

## Scope

Build controls for the new actions: hand/target selection, Basic-to-Bench, Energy, evolution, Item,
Supporter, Stadium, Tool, Ability, Retreat, Attack, Pass, and promotion. Illegal actions stay disabled or
hidden with a translated reason. Selection clears only after authoritative success. Support one pending
side, both pending after simultaneous KO, next-player-first promotion order, and no unrelated actions
between KO resolution and promotion. Keep `?local=1` on the shared `processAction` driver.

## Files

`PokemonBnbGame.tsx`, co-located styles, action/keyboard wiring, locales.

## Validation

Every action has success/rejection coverage; host/guest intent behavior; local harness parity; selection
lifecycle; single and simultaneous promotion ordering; build + lint.

## Progress

- [x] CP7 completed 2026-09-25.

## What shipped

- **New `controls.ts`** (pure, no React) — `controlStates(state, actor, selection)` returns
  `{ enabled, reason }` for all eleven controls, and `reasonKey()` maps a code to its
  `pokemonBnb.error.*` key. This is the single source of truth for what is playable; the component
  renders it instead of re-deriving rules that `processAction` already owns.
- **`PokemonBnbGame.tsx`** — the action bar is now data-driven (`CONTROLS` list → table → button):
  - **Item, Supporter and Stadium are separate controls** (they were one generic "Play trainer"
    button); Tool, Evolve, Retreat, Attack, Pass, Ability and per-attack buttons are gated by the
    same table.
  - **Every disabled control now explains itself** — `title` plus an `aria-describedby` hint
    pointing at one translated reason line. Previously a disabled button said nothing.
  - The promote gate follows `pendingPromotion` instead of the local seat, shows the queue order on a
    simultaneous KO, and takes its enable/reason from the same table as the bar.
  - The `?local=1` harness still drives everything through the shared `processAction` driver.
- Locales: 5 new `pokemonBnb.error.*` keys in en/ms/zh + the key union.

## Validation

- `scripts/cp7-assertions.ts` (throwaway, deleted after the run) — **15 assertions passed**: the
  selection gate, wrong-card-type reasons, Energy/Bench/Supporter/Stadium/Retreat limits, same-name
  Stadium, first-turn Supporter, phase and turn gating, everything closing on match-over, single-KO
  gating, simultaneous-KO next-player-first ordering, and no unrelated action between KO and
  promotion. A source check asserts the component imports the shared table and the old inline gate
  is gone.
- en/ms/zh parity: **613 keys**, 0 missing.
- `npm run build` passed; `npm run lint` 0 warnings / 0 errors.

## Bugs found and fixed during validation

1. **The hot-seat harness could deadlock on a simultaneous KO.** The promote gate only rendered for
   the local seat, so a second KO had no promote path and `?local=1` was stuck. The gate now follows
   `pendingPromotion`.
2. **`promote` was short-circuited to the blocking reason.** In the pending-KO branch every control,
   including `promote`, returned `must-promote` — so the gate could never be enabled. `promote` is
   now the one exception and is evaluated properly.

## Notes

- Selection still clears only on authoritative success (unchanged from CP8-B/CP9); the guest's
  selection is held until the host's snapshot arrives, which is deliberate.
- No persistence change and no diagram change; both remain scheduled for CP10.
