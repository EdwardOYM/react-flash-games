# 03.2.CP8 — B&B PackStack-Based Card Reveal

> Parent: `03.2-Pokemon-B&B-revamp-plan.md`. Depends on CP7.

## Scope

Reuse the shipped PackStack interaction without coupling game state. Prefer generalizing/extracting the
presentation primitive to accept plain `CardDef[]`, reveal flags, and expanded state; adapt Pack Battle
and B&B boundaries separately and preserve Pack Battle behavior.

B&B behavior: one overlapping stack, deterministic fixed-order reveal, one transparent action target,
latest revealed card visible, earlier cards mounted but not exposed, Reveal All immediate expansion,
completed focus retained, mirrored progress, and no auto-advance. All reveal state is session-only.

## Files

Shared/generalized `PackStack` component/CSS, B&B opening state/component/styles, protocol only if needed,
locales.

## Validation

960×540, mobile landscape, 390px portrait, one action target/latest exposed card, reveal-all expansion,
hidden-card accessibility, reduced motion, Pack Battle regression, build + lint.

## Progress

- [x] CP8 completed 2026-09-25.

## What shipped

- **Extracted the shared primitive** to `src/games/cardstack/PackStack.tsx` + `PackStack.css`.
  The shipped Pack Battle `PackStack` was **already behaviour-generic but data-coupled**: it was typed
  to `BattleOpenedCard[]` and lived inside the Pack Battle folder, so B&B could not have reused it
  without a second implementation. It now:
  - accepts plain `CardDef[]` plus reveal flags and expanded state, so it holds no knowledge of
    packs, seats, tiers, points, or ceremony state;
  - passes the plain `CardDef` to the `cardClassName` / `renderCardOverlay` hooks, so a consumer
    decorates cards without the stack knowing about the game;
  - is imported by **both** games; the old copies are deleted and the `ppb-pack-stack*` classes
    were mechanically renamed to `pkcs-stack*` (verified zero stragglers).
  Reveal behaviour is unchanged for Pack Battle, which still renders two seat lanes, tier flair
  and points chips — only the module boundary and class prefix moved.
- **`PokemonBnbGame.tsx`** — the opening view now renders the shared stack instead of a flat
  `bnb-card-grid` of every card:
  - the reveal is a deterministic **prefix** of the shared seeded pool, so both seats always expose
    the same card at the same index (mirrored progress);
  - one transparent action target replaces the old "Reveal next" button;
  - **Reveal All now expands** the stack in place for side-by-side review (`openingExpanded`);
  - **no auto-advance**: a finished stack stays focused until this player readies up.
- Locales: one new `pokemonBnb.revealCardLabel` key in en/ms/zh + the key union.

## Notes

- The reveal remains **local per client**, gated by the existing `opening-ready` handshake: the pool
  is identical from the shared seed, so both seats walk the same sequence independently and neither
  waits on the other. Wiring the reveal itself to the wire is CP9's synchronization scope.
- Reveal state is session-only (`useState`, reset in `resetMatchState`); no protocol message was
  added, so protocol v2 is unchanged by this checkpoint.
- No diagram change; that remains scheduled for CP10.
